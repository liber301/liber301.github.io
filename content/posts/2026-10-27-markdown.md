这是一篇入门示例文章，展示这个博客可以呈现的常见写作格式。可以保留作为参考，也可以换成自己的文章。

Markdown 用少量符号表达文章结构，适合把注意力留给内容。原始文件是纯文本，既容易编辑，也适合用 Git 保存修改记录。

## 先搭好文章的骨架

一篇笔记可以从三个问题开始：

1. 要解决什么问题？
2. 具体做了什么？
3. 留下什么结论？

标题负责划分层次，段落负责展开想法。这个博客会根据正文中的二级、三级标题，自动生成文章目录。

```markdown
## 遇到的问题

先说明背景，以及希望得到的结果。

## 尝试的过程

- 第一次尝试
- 得到的反馈
- 下一步调整

## 最后的结论

记下可复用的做法。
```

## 把重点留给重点

可以用 **加粗** 标出关键词，用 *斜体* 做轻微的强调。短命令、文件名或变量名适合写成行内代码，例如 `index.html`。

> 好的格式帮助阅读，但不需要让每一句话都变成重点。

### 链接与图片

链接写成 `[文字](网址)`。例如，可以从 [Markdown Guide 语法参考](https://www.markdownguide.org/basic-syntax/) 查阅常用语法。

图片写成 `![图片说明](/assets/图片文件名.jpg)`。为图片写清楚说明，也能帮助使用辅助技术的读者理解内容。

## 代码和表格也可以很清楚

代码块用三个反引号包裹，并标注语言：

```javascript
const thought = "先写下来，再慢慢整理。";
console.log(thought);
```

这个博客的代码块支持复制。涉及比较的信息，也可以放入一张小表格：

| 内容 | 适合的写法 |
| --- | --- |
| 一组平行的要点 | 无序列表 |
| 有先后顺序的步骤 | 有序列表 |
| 几个对象的比较 | 表格 |
| 可以直接运行的片段 | 代码块 |

## 写完之后，留一次回看

检查标题是否清楚，链接能否打开，段落有没有重复。再用手机看一遍，确认图片和代码块都能正常阅读。

一篇文章的第一稿，只需要把想说的事情说出来。后面的整理，可以慢慢来。
