这是一篇入门示例，介绍这个博客采用的发布方式。

一个主要承载文字和图片的个人博客，可以使用静态页面：先生成网页文件，再交给托管平台提供访问。访客打开文章时，无需等待一个应用服务现场拼装整篇页面。

## 三个环节，各做一件事

这个博客把发布过程分成三步：

1. **写文章**：在 `content/posts/` 中保存 Markdown 文件。
2. **生成网页**：构建脚本将文章、模板和样式组合成静态页面。
3. **公开访问**：GitHub Pages 托管生成的文件，提供 HTTPS 网址。

文章、分类、归档、RSS 和站点地图会一起生成。它们来自同一组内容，因此增删文章时不必逐个维护列表。

## 个人主页仓库的命名

GitHub 的个人主页仓库采用 `用户名.github.io` 的命名方式。这个博客对应的仓库是：

```text
liber301/liber301.github.io
```

发布后的默认网址是 [liber301.github.io](https://liber301.github.io/)。托管平台负责响应访问，个人电脑不需要一直开机。

## 让更新随着提交发布

这个仓库使用 GitHub Actions 执行构建和部署。每次向 `main` 分支推送文章或样式修改，发布流程就会重新生成网站。

可以在本地先检查：

```bash
npm ci
npm run build
npm run check
npm run preview
```

确认内容和页面正常，再提交并推送修改。发布进度可以从仓库的 Actions 页面查看。

## 留一个清晰的起点

第一版博客不必同时加入所有功能。清楚的文章结构、顺畅的阅读体验，以及可重复的发布流程，已经能支持长期更新。

更详细的操作可以参考 [GitHub Pages 官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。
