这是一篇入门示例，说明这个博客目前采用的发布方式。

个人博客可以公开分享，也可以只留给自己或指定的读者。两种用途对访问权限的要求不同，选择托管方式时应一起考虑。

## 页面生成，和访问权限

这个博客使用 Markdown 保存文章，再将文章、模板和样式组合成静态网页。文章列表、分类、归档和搜索索引都从同一组内容生成。

静态网页也可以放在支持账号登录的托管平台上。真正的访问控制发生在服务器或平台收到请求时，而不是等文章已经下载到浏览器后再遮住内容。

## 为什么调整托管方式

GitHub Pages 适合公开的静态网站。普通个人站点没有原生的账号密码访问控制，不能只在首页放一个输入框，就认为文章、RSS 和其他文件已经得到保护。

这个博客目前采用私有托管，通过 ChatGPT 账号登录并校验访问权限。默认仅站点所有者可以阅读，新增读者需要单独授权。

## 在本地写，再同步源码

文章和代码保存在本地 Git 仓库中。修改后，可以先构建和检查：

```bash
npm run build
npm run check
npm run preview
```

确认页面效果后，提交修改并同步到私有 GitHub 仓库。GitHub 在这里承担源码版本管理的作用；推送源码与发布私有网站是两个步骤。

## 发布一个私有版本

私有站点的发布流程会构建网页、检查链接、保存源码版本，然后将同一版本的网页部署到平台。

发布后，文章直链、搜索索引和 RSS 也会受到访问控制。站点不会因为新增一篇文章，就重新启用旧的公开发布入口。

## 给长期记录留一个简单的结构

文章放在文章目录，样式放在样式文件，源码保留版本记录，访问权限交给托管平台处理。职责清楚，后续修改和维护也会更容易。
